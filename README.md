## Собственный проект

тема проекта: магазин

главный класс: Product

почему этот объект нужен программе:
класс нужен чтобы не создавать кучу отдельных переменных для каждого товара а хранить все данные об одном товаре в одном месте

какие данные хранит объект:

- Name - название товара
- Price - цена
- Category - категория
- Stock - количество на складе
- IsAvailable - есть ли товар в наличии

какие значения задаются через конструктор:
название цена категория и остаток на складе потому что эти данные у каждого товара свои

какие значения можно задавать автоматически:
поле IsAvailable задается автоматически как true потому что когда добавляешь новый товар в магазин он обычно сразу есть в наличии

## Практическая работа №3

исправление ошибок:
1. ошибка: `public int Health { get; set; }` давало менять здоровье снаружи -> исправила на `public int Health { get; private set; }` -> теперь напрямую присвоить здоровье нельзя, вылетает ошибка компиляции.
2. ошибка: `value.Trim(); _name = value;` не убирало пробелы -> исправила на `_name = value.Trim();` -> пробелы по краям теперь удаляются, имя `"   Александр   "` стало `[Александр]`.

ответы на вопросы:
1. `private set` вообще запрещает менять свойство извне класса, а проверка следит, чтобы число внутри было нормальным. начальное здоровье проверяется в конструкторе `Hero`, а при игре — в методах `TakeDamage` и `Heal`.
2. когда в конструкторе пишем `Name = name;`, переданное имя попадает в `value` внутри `set`, там оно чистится через `Trim()` и сохраняется в поле `_name`.
3. правило `0 <= Health <= MaxHealth` проверили на разных числах: при создании `-100` вышло `0/100`, при `5000` ограничилось до `200/200`, лечение на `5000` остановилось на максимуме `150`, а урон `5000` опустил здоровье до `0`.

### Самостоятельный шаг (Магазин)
правило: остаток товара на складе (`Stock`) не может быть меньше 0.
где проверяется: сделала `private set` у свойства `Stock`, в конструкторе `Product` отрицательное число заменяется на `0`, а в методе `AddStock` неположительное число просто игнорируется.
результат проверки: при создании мышки с остатком `-5` на складе записалось `0`, а при попытке добавить `-2` к остатку ноутбуков (`8`) число не изменилось и осталось `8`.
